STEP 1 — the API key
---------------------
Netlify -> Site configuration -> Environment variables -> Add

    Key    ANTHROPIC_API_KEY
    Value  your key from console.anthropic.com

Then Deploys -> Trigger deploy -> Clear cache and deploy site.
Environment variables only take effect on the next build.

The key is read server-side inside the function. It is never sent to
the browser and never goes in the repo.

No second passphrase. The builder reuses MOSAIC_WRITE_KEY.

HOW IT WORKS
------------
An SBU leader fills in a short brief: unit, what to promote, goal,
audience, channels, optional budget and timeframe.

Before anything is sent anywhere, the browser assembles evidence from
data already in this app:

  - keywords for that unit matching the focus, with real spend,
    conversions and CPL, split into converting and not
  - keywords burning money with no conversions, as negative candidates
  - channel performance for that unit from the grid
  - inbound demand from the contact wizard: how many leads asked for
    this, through which channels, in which categories

That panel renders immediately and costs nothing. It is worth reading
on its own.

Only then does Generate send the brief plus that evidence to the
model, which returns:

  1. Where this stands today
  2. Keywords — already converting vs worth adding, plus negatives
  3. Campaign structure — Google ad groups and budget, LinkedIn
     targeting with an audience size check, email placement
  4. Ad copy and subject lines — RSA headlines and descriptions with
     character counts, LinkedIn variants, 5 subject lines
  5. Landing page brief — slug, H1, sections, CTA, proof, FAQ
  6. A complete SFMC-ready email as an HTML block

Two download buttons: the whole plan as markdown, and the email HTML
on its own.


WHY IT STREAMS
--------------
A Netlify function has ten seconds to respond and this takes longer.
The limit applies to the first byte, not the last, so the response is
piped through as it is written. You watch the plan appear instead of
watching a spinner.


ON THE OUTPUT
-------------
The model is instructed never to invent a number. Figures in the plan
come from the evidence, and anything it cannot source it is told to
flag rather than estimate. It is also told to separate what already
converts from what it is proposing — evidence versus hypothesis.

That instruction reduces invention. It does not eliminate it. Check
the numbers in a plan before it goes to Jeff or Gregory, particularly
any figure that sounds better than you expected.

The LinkedIn section carries a hard-coded warning about the $2,336 on
274 people at a $1,523 CPM, so every plan has to state a minimum
viable audience size.


COST
----
Each Generate is one API call, roughly 6,000 tokens in and up to
8,000 out. Pennies per run at Sonnet pricing, but it is not free and
the site has no login — the passphrase is the only thing between the
URL and your API balance. Every run is logged to the blob store under
campaign/runs with a timestamp, the name entered and the focus, so a
runaway is visible.


IF THE PLAN LOOKS THIN
-----------------------
It reflects the evidence. A unit with no keyword data gets proposals
only, and the plan says so. Import a Google Ads search keyword report
on the grid tab and publish the form fills data, and the same brief
produces a much sharper answer.
