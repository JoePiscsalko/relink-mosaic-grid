CAMPAIGN BUILDER — the actual cause
====================================

One file:

    netlify/functions/campaign.js

Add file -> Upload files, drag in the "netlify" folder, commit.
No client change needed — the build you have is fine.


WHAT THE DIAGNOSTIC SAID
------------------------
    The API sent 8 events but no text.
    It stopped with reason: max_tokens.

Eight events, none of them text, and it ran out of room. The model was
spending its entire budget on extended thinking and never reaching the
writing.

Extended thinking is on by default for this model. Those tokens come
out of the same allowance as the output, and they arrive as
thinking_delta rather than text_delta — so the parser, which only
forwards text, saw nothing at all to send.

This was behind every failure in the chain, not just the last one:

  - The first 60 second timeout: thinking is slow and was consuming
    the budget before any writing started
  - The larger budgets that sometimes worked: enough room left over
    to think AND write
  - Shrinking passes to 1,500 tokens: guaranteed there was nothing
    left after the thinking, which is why it went from intermittent
    to failing every time

My budget tuning was making it steadily worse. Smaller passes were
exactly the wrong direction, and I could not see it because "empty"
was all the app could tell me.


THE FIX
-------
    thinking: { type: "disabled" }

One line on the API request. A campaign section does not need a
scratchpad, it needs the words. With the whole allowance going to
output, passes went back up to 2,200 tokens and start producing
immediately.

The diagnostic also now recognises this case specifically. If thinking
is ever switched back on, the panel says so by name instead of leaving
you to work it out.


WHAT TO EXPECT
--------------
Text appearing within a few seconds of each pass starting, seven
passes, two to three minutes end to end.


ON THE LAST FIVE ATTEMPTS
--------------------------
Four of them were me guessing. The one that worked was the one that
