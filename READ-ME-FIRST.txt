WHAT CHANGED FROM YOUR VERSION
-------------------------------
Your calendar used window.storage, which exists inside Claude
artifacts and nowhere else. On Netlify there is no such object, so
every read and write would have thrown and the calendar would have
looked permanently empty. It now talks to /api/calendar, backed by
the same Netlify Blobs store the grid and Form Fills use.

Everything about the design is yours. What is different underneath:

1. Images are fetched per entry, not all at once. A month of social
   posts is a lot of base64 to pull down on every page load for cards
   nobody opened.

2. Writes ask for the passphrase -- the same one the grid uses -- once
   per session rather than every change. Without it, anyone who found
   the URL could quietly delete a month of planning. Reading needs
   nothing, so Jeff and Gregory can look without a passphrase.

3. Saves write to the server first, then update the screen. Your
   version updated the screen first, which meant a failed save left
   you looking at an entry that did not exist for anyone else.

4. alert() replaced with an inline message in the dialog.

5. Font set to Source Sans 3 to match the other two tabs.

6. Old entry types (email_buyer, auction, linkedin and so on) migrate
   forward on read, same as your version did.


WHERE IT LIVES
--------------
    marketing-grid.netlify.app             the grid
    marketing-grid.netlify.app/#forms      form fills
    marketing-grid.netlify.app/#calendar   the calendar

Every write is backed up under calendar/backup/<timestamp>, so a bad
delete is recoverable.
