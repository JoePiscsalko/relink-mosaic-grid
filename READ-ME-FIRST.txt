WHY THIS BUILD EXISTS
---------------------
I have guessed wrong about this four times running, and each guess has
cost you an upload and a wait. "Stage 1 came back empty" tells us
nothing about why, so I have been theorising instead of knowing.

This build stops the guessing. When a pass produces no text, the
function now reports what it actually saw, in the panel, in plain
words. Two possible answers:

  "The API accepted the request but sent nothing back before the
   connection ended. That usually means the function was cut off at
   its time limit."

     -> the 60 second kill, despite the smaller budgets. The fix is
        architectural: a background function that polls, rather than
        a request that has to finish inside a minute.

  "The API sent N events but no text. It stopped with reason: X.
   First event: {...}"

     -> the request reached the model and something else went wrong.
        The stop reason and first event name it exactly.

Either way the next run answers the question instead of raising it.

The run also halts at that point rather than building five more
sections on top of a hole, and the explanation stays on screen.
