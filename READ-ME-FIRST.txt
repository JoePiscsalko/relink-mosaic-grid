CAMPAIGN BUILDER — keep-alive fix
==================================

Two files:

    src/CampaignBuilder.jsx
    netlify/functions/campaign.js

Add file -> Upload files, drag in BOTH folders, commit.


WHAT THE LOG SHOWED
-------------------
    09:47:08  Duration: 32434.69 ms

Stage 1 ran for 32 seconds and finished cleanly. No crash, no timeout,
well inside the 60 second ceiling. The function did its job — the
browser just never received it.

That is a different failure from the last two. The proxy sitting in
front of the function closes the connection to the browser if no bytes
arrive soon enough, and this stream sent nothing at all until the model
produced its first token. The model spends the first several seconds
reading the brief before it writes anything, so the connection was
being cut while the function carried on working into the void.

Hence "Stage 1 didn't come back" while the log said it plainly had.


THE FIX
-------
The function now sends a byte the instant the stream opens, and keeps
sending one every three seconds until real text starts flowing. It is
a zero-width space — invisible in the rendered plan, and the browser
strips it anyway. It exists only to keep the pipe warm.

Measured against an upstream deliberately stalled for 7 seconds:

    first byte before the fix   ~7,000 ms
    first byte after the fix        49 ms
    text delivered intact           yes

Stage errors now also report the HTTP status, so if anything else goes
wrong the message says what happened rather than shrugging.


WHAT TO EXPECT
--------------
Generate, and within a second the heading should show
"1 of 5 - the idea" with the pulsing dot. Text begins appearing a few
seconds later. Five passes, roughly two minutes end to end.

If a pass still fails, whatever was written stays on screen and the
error names the stage and the status code.
